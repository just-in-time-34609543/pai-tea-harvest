# 点群AIによる茶の成葉の選択摘採ロボット

Physical AI応用1 最終課題　説明資料（数値はすべてシミュレーションの結果で、実機・実茶樹での結果ではない） PDF版は `scripts/make_report_pdf.py` で作る（`docs/report/report.pdf`）。

動画：https://www.youtube.com/watch?v=ZV-F6PxgfTw　コード：https://github.com/just-in-time-34609543/pai-tea-harvest

## 1. 課題の概要と目的

茶の成葉を収穫するには、摘む葉と残す枝・葉柄を見分け、枝を傷付けずに1枚ずつ摘み取る必要がある。本課題では、ビニールハウスの天井レールを走る台車から吊った台に小型ロボットアーム（Adeept ADA031）を載せ、ハウスの骨組み（アーチ）に付けたカメラの点群から、言葉で指定した成葉をAIが特定し、1枚ずつ摘んで回収箱へ入れるまでを自動で行うシステムを、物理シミュレーション（MuJoCo）と写実的なレンダリング（Unreal Engine）で構築・評価した。

## 2. タスク設定と成功条件

- 場面：実運用想定のパイプハウス（幅5.7m×長さ10m×高さ3.1m、アーチ12本）に高さ1.5〜2.1mの茶樹。天井レールの台車から吊った台に、Adeept ADA031（5自由度、2本指グリッパー）を載せる。
- 1回の試行：台のまわりの樹冠から、摘む対象の成葉（緑の葉）が3枚立ち上がっている。指示文は4種類で固定（英語。「成葉を1枚摘んでかごへ」「左の成葉を…」「真ん中の成葉を…」「右の成葉を…」）。
- 成功：指定した成葉（任意の場合はどれか1枚だけ）を摘み、かごの中へ入れ、他の成葉は株に残り、グリッパーを開いている。葉柄と枝は株に残る。
- 摘み取りの模擬：成葉は株（葉柄）に拘束されており、指で挟んで上へ引いたときだけ外れる。摘めたかどうかは、指の接触・グリッパーの角度・引き上げで判定し、どの葉でも同じ条件（切断・柔らかさ・損傷は未モデル化）。

## 3. システム構成と処理の流れ

```text
アーチ上のRGB-Dカメラ4台＋手首カメラ（Unreal Engine 5.7で描画、深度つき）
        ↓ 各カメラの外部パラメータで台座標へ逆投影・統合（2048点、xyz+色）
AI：点群＋指示文 → 指定された成葉の3D把持点
        ↓
逆運動学でアームの関節角を計画 → 接近 → 把持 → 引き抜き → かごへ移動 → 解放
        ↓
成功判定・記録
```

## 4. AIを活用した箇所と、その必要性

成葉の位置は株ごと・試行ごとに変わり、茶樹のほかの葉や枝と同じ緑色で重なって見える。決まった座標を巡回するだけでは指定の成葉を摘めないため、カメラの点群と指示文から「どの成葉を、どこで掴むか」をAIが推定する。動作の計画（接近・把持・引き抜き・かごへの移動・解放）は、AIの推定点だけを使って逆運動学で行う。かごへの落とし位置の補正も、指を閉じた時点の推定点とグリッパー先端の差から求め、シミュレーターの正解の位置は使わない。

AI：点群（最遠点サンプリングで128中心、各32近傍の局所PointNet＋中心座標のFourier埋め込み）と指示文の特徴（SmolVLM2-500M の言語モデルを凍結、文全体の平均）を Transformer で統合し、目標の成葉の3D位置を回帰する。学習データは、逆運動学によるお手本の成功エピソードのみ（MuJoCo描画400話、Unreal描画60話。各指示で均等）。

## 5. 結果

評価は、学習に使わない乱数シード（100000〜100009）で各指示10試行、計40試行。

| 方式（学習データ） | 任意 | 左 | 真ん中 | 右 | 平均 |
|---|---|---|---|---|---|
| Unreal描画で評価（Unreal 60話＋MuJoCo 400話で学習） | 90% | 90% | 90% | 100% | 92.5% |
| MuJoCo描画で評価（MuJoCo 400話で学習） | 80% | 100% | 100% | 100% | 95% |

- 写実的なUnreal描画でも、AIは指示された成葉を点群から特定して摘み取れた（平均92.5%、推定誤差の中央値7.7〜8.4mm）。
- MuJoCoだけで学習したモデルのUnreal画面での評価は、時間の都合で成葉版では行っていない（MuJoCo画面では95%）。
- 言い換えた指示（各指示3文×10試行、事前登録して固定）での成功率は、Unreal＋MuJoCoで学習したモデルをMuJoCo描画で評価して63.3%（同じ条件で元の文は87.5%、相対28%の低下）。指示文は4種類に固定で、言い換えには対応していない。固定の4文で学習し、言い換えは評価だけに使った。
- 動画の4試行（各指示1試行、seed 100003、100001、100002、100004）は結果を見る前に決めた代表例で、成功率は上の40試行の評価による。動画は10fpsのシミュレーションを10fpsで書き出した等速で、倍速部分はない（タイトルと終わりの画面は静止画）。

## 6. 工夫した点と、前の版から発展させた点

- 前の版（同じリポジトリの main ブランチ、v7）は、天井吊りの2関節アームと球殻グリッパーで、決まった位置の葉を順に回収するもので、AIは使っていなかった。本版では、言葉で指定した成葉をAIがカメラの点群から探して摘む形に発展させた。
- 物理はMuJoCo、描画はUnreal Engineで分担し、MuJoCoで計算した全物体とカメラの姿勢を毎ステップUnrealへ送って、画面のないGPUサーバーで写実的なRGB画像と深度を得る仕組みを作った。UnrealRoboticsLab（MuJoCoとUnrealの連携）の考え方を参考にしたが、そのままでは画面なし環境でカメラ画像が出ず、複数起動で停止したため、姿勢を送る方式に置き換えた。
- 茶樹・パイプハウス・地面は、実際の茶樹の写真を参考にプログラムで生成した。外部の3Dアセットは使っていない。
- 方式の選定：開発の途中（株の先端の芽を摘む課題としていた段階）で、動作までAIが出すエンドツーエンド型（点群VLA、SmolVLA）と比べ、少数のデモでは「どれか・どこか」をAIが推定し動作は運動学で計画する役割分担型が最も確実だったため（Unreal描画で役割分担型97.5%、点群VLA 75%、MuJoCo描画でSmolVLA 5%）、成葉版では役割分担型を採用した。

## 7. 実装と使用した主な技術

物理シミュレーション MuJoCo 3.17.0、描画 Unreal Engine 5.7.4（Lumen、画面なしのVulkan）、学習 PyTorch 2.10.0、指示文の特徴 SmolVLM2-500M-Video-Instruct、比較用VLA LeRobot 0.4.4 のSmolVLA。アームはAdeept ADA031（5自由度、2本指グリッパー）のシミュレーションモデル。

## 8. 失敗例と考察

- 成葉は薄く軽いため、離したあとグリッパーに挟まったまま残ることがあった。葉の当たり判定を短くし、葉身の下半分を挟むようにして、お手本の成功率を100試行中98回にした。
- 掴んだ葉はグリッパーの中心からずれてぶら下がるため、かごへの落とし位置を、指を閉じた時点の推定点とグリッパー先端の差で補正した。
- デモの記録を成功判定の瞬間で打ち切ると、グリッパーを開き切る動作が学習データに入らず、方策が「離す直前」で止まった（開発途中の点群VLAで発見）。記録をお手本の最後まで延ばして解決した。
- 言い換えに弱い理由：学習に使った4文は位置を表す1語だけが違い、言語モデルの文全体の埋め込みでは位置の違いがごく小さな差にしか表れないため、言い換えるとその差が崩れて目標の位置を取り違える。

## 9. 制約と今後

- 成葉は剛体の模型で、切断・柔らかさ・損傷は扱わない。成葉は株の上部に立っており、遮蔽は少ない。
- 実写の茶葉での認識は未実施。実機（Adeept）への移行には、カメラ校正と実測点群での追加学習が必要。
- 指示文は4種類に固定。改善の方向：学習のときに言い換えの文を混ぜて位置の語の意味を学ばせる、文全体を平均した埋め込みの代わりに語ごとの埋め込みなど位置の語が埋もれにくい表し方にする。
- 摘む／残すの判断は指示文の位置指定で代用しており、収穫に適した葉そのものの識別は今後の課題。
